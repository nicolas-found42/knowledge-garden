# Mixed-material trails

Open **Trails** while reading. Add the current page, select a unique source passage and add it, or choose an existing source message or decoded media location. Stops can revisit the same material, be removed or moved with keyboard-accessible buttons, and be followed with Previous/Next. Return to trail origin restores the starting view. Merely following or editing the route creates no permanent record.

**Save this trail** explicitly creates a named definition in `views/*.md`, using the same Markdown identity, safe rename and recoverable removal contract as saved views. Find and reopen it through **Saved views**. The YAML contains ordered stop identities and contextual references; readable links and an ordered list remain usable independently. Session position and resolved content are temporary.

Page stops resolve current identities, including external moves and renames. Passages bind an exact source version, basis and UTF-8 range; repeated selections are rejected instead of guessing. Messages retain their supplied identity, and media locations derive from retained transcript segments or decoded frames. A changed source version, removed target, altered passage or unavailable message stays explicitly unavailable in its original position. A separate action can open the current source, or the exact older original when retained. No obsolete page facts or similar passages are substituted. Media original opening discloses manual seeking when precise playback is unavailable.

Suggested stops use a bounded shortlist of at most 12 existing search results and one independent Jev Noul per candidate. Code selects up to five current targets above the initial 0.7 policy threshold, ordered by estimated relevance. Suggestions use `typesafe/jev-1.14` through the existing server-side OpenRouter transport; the older semantic extraction pin remains unchanged. The network request runs outside the collection mutex, and each selected identity and its input content are checked again afterward. Unavailable credentials, quota or model capability produce an explicit unavailable state with no fallback service or invented stop. The response retains reported model, token/cost fields when supplied, and measured latency for qualification; these are not evidence of connection correctness.

The four native integrity scenarios cover mixed page/event/passage/message/media stops, reordering/removal, explicit save, restart, derived-index rebuild, owner page move/rename, source removal, changed wording/version, and frozen Jev candidate selection. UI scenarios cover keyboard reordering, traversal/return focus, explicit saving/reopening and cancellation after a route edit. Frozen provider results establish application integrity only; independent live semantic quality and the selected 16 GB release machine remain separate gates.

The request shape and pin follow the [OpenRouter Jev hub](https://openrouter.ai/docs/guides/community/jev) and [System One transport guide](https://openrouter.ai/docs/guides/community/typesafe-sdk); selection questions follow TypeSafe’s [reranking cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe) and [Noul guidance](https://docs.typesafe.ai/primitives/noul). The controlled live smoke reported snapshot `typesafe/jev-1.14-20261014`, three acquired page/source stops, 885 input tokens, USD 0.00003717 and 188 ms transport latency. That single authored scenario verifies the integration, not retrieval accuracy.
