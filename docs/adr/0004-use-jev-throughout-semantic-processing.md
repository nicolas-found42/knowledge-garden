# Use Jev throughout semantic processing

Use Jev wherever semantic work can be expressed through choices, scores, or yes/no judgments, including chains composed with code, extraction tools, and allowed generative helpers. Keep exact copying, calculations, identities, workflow control, and file mutations in code, and restrict other general-purpose LLM work to the selected OpenCode Go DeepSeek v4.1 and GPT-6 Luna models without an application spending cap or silent provider substitution. [Specification #1](https://github.com/nicolas-found42/knowledge-garden/issues/1) records the observed verifier failures and requires independent quality evaluation, recoverable provider limits, and validation of service suitability and media capabilities; structured model output alone is not proof of correctness.
