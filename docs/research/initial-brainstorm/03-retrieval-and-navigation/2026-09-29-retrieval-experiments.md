# Retrieval beyond reranking: eight live Jev hypotheses

Research date: 2026-09-29. Status: synthetic development evidence, not an accepted architecture or production benchmark. This extends the [shared baseline](../01-knowledge-formation/2026-09-29-baseline-research.md) and [repository landscape](2026-09-29-repository-landscape.md). No product files, glossary or ADR were changed.

The useful finding is that Jev can select constraints, complementary evidence, original decisions, and known clarification questions. Selection accuracy alone does not make a complete retrieval workflow: omitted candidates, broad answerability prompts, and premature graph completion were material failures. The most promising compositions keep independent semantic judgments visible while code owns candidate identity, chronology, scope boundaries, traversal budgets and source copying.

## Method and artifacts

The [runnable laboratory](experiments/retrieval-lab/README.md) contains a realistic but wholly invented 20-source miniature corpus: household constraints, offline commuting, two projects' search decisions, original decisions and retrospective summaries, redundant revision explanations, quote-traceability mechanics, unresolved deletion policy, an unaccepted encryption suggestion, and a quoted instruction attack. Eight queries have predetermined relevant-source sets and acceptable best-answer sets. Source IDs, full state and question wording, probabilities, raw successful responses, latency, usage and cost are retained in [initial results](experiments/retrieval-lab/results-initial.json), [follow-up results](experiments/retrieval-lab/results-followup.json), and [machine-readable analysis](experiments/retrieval-lab/summary.json).

All initial labels were written before requests. Follow-up prompts and compositions were informed by observed failures; no untouched holdout exists. Fixtures overlap: 160 query/source judgments are eight queries against the same 20 sources, not 160 independent real-world tasks. The six evidence-bundle states, four temporal queries, four clarification states and three graph goals also reuse the corpus. We evaluate authored labels and concrete evidence coverage, not a generated answer. Jev returns typed judgments; this experiment does not evaluate prose synthesis or agent task success.

The lexical baseline is a transparent set-overlap ranker with a small stopword set and stable source-ID tie breaking. It is deliberately basic: these results do not establish superiority over tuned BM25, embeddings, hybrid retrieval or a real vault. Its purpose is to make missing-candidate failures observable.

The implementation uses TypeSafe Python SDK 0.7.2, explicit OpenRouter key and base URL, and `typesafe/jev-1.13`; every successful response resolved to `typesafe/jev-1.13-20260917`. Named source dictionaries avoid numeric array indirection. Each independent pair request batches its Noul and Score; broad selection batches Choice and answerability. Graph requests depend on the prior observed hop. Six independent requests run concurrently. All input is synthetic/public; secrets were never written into records.

The completed study made **257 successful API calls containing 547 questions**, using **150,805 input tokens and 12,784 output tokens**, at **$0.006333810 reported cost**. Median request latency was **0.364 seconds**. The initial 224-call run took 20.906 seconds with six concurrent independent requests and sequential graph hops. No service failures were recorded. Cost comes from successful raw provider JSON, rather than a zero default in SDK serialization. These short contexts establish no real-vault scale or monthly budget.

## Results by hypothesis

| Hypothesis and comparison | Observed result | What it establishes and what it does not |
| --- | --- | --- |
| H1: broad recall can recover evidence omitted by a lexical shortlist | Lexical top 1 found an acceptable answer on 2/6 answerable queries; top 3 contained one on 3/6. Broad Choice selected gold or none on 8/8; shortlist Choice on 5/8. | Three shortlist misses are candidate recall failures. Broad selection works for this small source pool; whole-vault recall and context scaling remain untested. |
| H2: independent judgments find relevant constraints with little vocabulary overlap | Independent relevance Nouls matched 148/160 authored binary labels at 0.5. Both Noul and directness Score ranked an acceptable source first on all six answerable queries. | Scores distinguish answer quality from useful context. Twelve relevance disagreements remain; several concern partial relevance near 0.5. These are not calibrated operating thresholds. |
| H3: marginal usefulness selects complementary evidence instead of repeated context | Bundle Choice matched 6/6 acceptable next-source sets, including two none outcomes. | A selected preservation reason made traceability mechanics win over a paraphrase; when mechanics were selected first, a reason won. Complete-answer judgment was less reliable than next-source selection. |
| H4: retrieval can retain counterevidence while selecting current scope correctly | Four bounded temporal/scope Choice queries matched 4/4, including an absent benchmark. | Sorting dates in code plus explicit source roles supports current versus replaced decisions. The model did not independently validate chronology or external truth. |
| H5: observed-edge navigation can find evidence, but goal completion needs a stricter contract | Initial greedy trace followed the expected four nodes, but search took the wrong branch. A breadth-two follow-up found the original search decision; broad completion also stopped a trace path before mechanics. | Link selection, evidence sufficiency, and stopping are separate judgments. Neither an existing graph edge nor a high goal Noul proves that every requested facet is covered. |
| H6: bounded clarification can distinguish ambiguity from a genuine missing fact | Initial action-plus-question checks matched 6/8; explicit follow-up wording matched 7/8. The already-answered format fact still became a gap. | Known candidate questions are selectable without generating questions. One false gap remains on a simple explicit fact; this workflow needs its own evaluation. |
| H7: reusable semantic axes support preference changes without repeat inference | Twenty sources received three Scores each; local weights produced different planning, implementation and audit lists with zero further calls. | Preference recomposition is mechanically demonstrated. There are no preference-ranking gold labels or usefulness measurements. Scope and eligibility should not be traded away by weights. |
| H8: Choice shares differ from independent relevance and need not move monotonically with equivalent options | Four irrelevant-distractor variants and four true equivalent-answer variants all selected valid sources. Equivalent candidate count changed selected-source probability and confidence non-monotonically. | Distractor robustness and equivalent-answer competition are different tests. No universal probability correction or confidence threshold follows. |

### Candidate recall, ranking and answerability

For “What limits scheduling a loud power-tool job before supper?”, `quiet_hours` says the partner sleeps beside the study during daylight after working nights. It shares no substantive query tokens with the lexical baseline. Broad Choice selected it at 0.70; the lexical shortlist omitted it and correctly returned none. A ranking model cannot repair that shortlist.

Three other queries illustrate a different issue. A broad answerability Noul was only 0.38 for the household constraint despite selecting the right source. Lexical-shortlist answerability was 0.35 for the commuting constraint and 0.40 for the preservation reason even though the needed evidence was present. The initial question demanded a “complete answer,” including acceptance, scope, time and reason even when those dimensions were irrelevant to the query. That overbroad evidence contract can suppress a usable constraint.

The initial raw checks compare against corpus-level answerability, including when called on a shortlist. Those raw labels remain frozen. The offline analysis additionally measures **supplied-state answerability**: expected yes only when that supplied pool contains an acceptable answer. This corrected metric is 13/16 across broad and shortlist requests. Accurate no-answer responses on omitted evidence are classified as candidate recall failures. The refined, atomic broad-pool question matched 8/8, with answering cases at 0.73–0.93 and missing cases at 0.06/0.10. This same-fixture development improvement is not held-out evidence.

Independent relevance and directness answer different questions. `new_summary` may help locate a past choice but does not independently establish its original acceptance. The attack source establishes that a quoted approval instruction is untrusted but says nothing about an encryption algorithm. Its predetermined useful-counterevidence label was generous; Jev gave it 0.11. Several revision/rebuild disagreements are plausible partial-evidence boundary disputes. Raw disagreements are in the summary; no labels were retrospectively changed to inflate agreement.

The six answering queries had an acceptable source at rank 1 under both independent methods. On the two missing-answer queries, an independent ranking still produces a winner. It needs a separate presence/acceptance check, or a user interface that clearly describes related evidence rather than asserting an answer exists. Choice with none selected abstention on both missing queries.

### Complementarity and source disagreement

For “Explain why revisions are immutable and how quotes stay traceable,” selecting the preservation reason first yielded the mechanism source with Choice probability 1.00; its novelty Noul was 0.94 and the duplicate reason 0.13. With the mechanism selected first, the original reason won at 0.92. This is a context-budget experiment: the marginal judgment sees what is already selected. A global relevance list does not supply that relationship.

When the current search choice was already selected and the goal requested what it replaced, the old choice won at 0.76 over a retrospective summary and an unrelated project's current choice. Old evidence remains useful when its historical role is explicit. Four temporal queries correctly selected Garden's current choice, Garden's superseded original choice, Payments' current choice, and none for an invented performance benchmark. Code parsed/sorted dates; chronology was supplied as observed order. These results are source-role judgments, not evidence that model text comparisons safely replace timestamp arithmetic.

The complete bundle still received a complete-answer Noul of 0.45 even while next-source Choice correctly stopped. This differs from the graph's opposite error below: composition must preserve the question meanings rather than assume that distinct probability outputs obey shared invariants.

### Bounded graph exploration and stopping failure

The seven-node graph exposes only actual outgoing links, target previews, visited evidence and the goal. Code prevents revisits and bounds depth to five; the beam variant also bounds frontier width and calls. Initial greedy traversal collected `garden → import → revisions → mechanics` for the trace goal. Its final reached Noul was 0.58, below the illustrative 0.70 stopping threshold, so termination was “no useful link” despite full gold evidence coverage. For the original search-decision goal, the first hop preferred import at 0.51 over search at 0.45 and continued down the wrong branch. Ten per-hop binary checks happened to match at 0.5; that is **not** ten successful graph tasks.

The follow-up changed wording, link descriptions, breadth and completion threshold together. It found `garden → search → choice` and an evidence-supported completion at 0.79. It also declared the trace complete at `garden → import → revisions` with probability 0.73, before reading the quote-traceability mechanism. The preservation reason alone does not supply message IDs or the saved-source mechanism. The initial goal's phrase “quotes stay traceable” left room for a broad interpretation; this is both a goal-contract weakness and an evidence-coverage failure under our required-facet labels. Exact expected path and verified required evidence coverage are tracked separately. The missing encryption goal produced no completed path in either variant.

A focused extension makes both facets explicit: preservation motivation, and a concrete method connecting quoted spans to saved source bodies through message IDs, offsets or equivalent references. The facet experiment keeps the two Nouls separate and lets code require both before declaring completion. Its raw trace and per-facet gold coverage are retained in [facet results](experiments/retrieval-lab/results-facets.json). The three-hop extension took `garden → import → search` and stopped with no useful link, missing both required evidence pages. At import it also assigned preservation-reason probability 0.60 to an overview that gave no actual motivating failure. Requiring both facets prevented a false success in this trace, but did not make link selection succeed. The narrower goal and greedy selection changed together, so this does not isolate the cause. This is another development probe, not a proven general stopping policy. A model may misjudge an individual facet too; code should distinguish an exhausted frontier, a budget stop and verified evidence completion.

### Clarification, cached qualities and equivalent answers

The clarification experiment supplies fixed candidate follow-up questions and never asks Jev to write one. It correctly chooses “Which project?” when Garden and Payments have different search choices, and a question offering to decide a policy when deletion is explicitly unresolved. It avoids the candidate question “On which date was encryption accepted?” when encryption was never accepted. However, the source fact “Canonical Garden notes are ordinary Markdown files” was initially treated as a gap and prompted an unnecessary project question. Explicit wording removed the unnecessary question but still selected gap at 0.57 versus answer at 0.41. This unresolved error should remain visible.

Three query-independent qualities were cached: behavioral constraint, concrete procedure and decision/evidence provenance. A local implementation weighting ranks `revision_how` first at 0.812; an audit weighting ranks the duplicate preservation reason first at 0.928; a planning weighting also ranks that requirement first, with the household constraint in the top three. These are legitimate semantic features for interactive views, but broad corpus-wide preferences can mix unrelated projects. The experiment demonstrates zero-call recomposition only. It does not measure whether a human prefers these lists, prove that a note is true, or show that scores should override scope eligibility.

H8 first adds irrelevant noise headings: quiet-hours Choice remains 0.64–0.71 across zero, two, six and twelve distractors. A distinct follow-up adds one, three or seven equivalent correct constraint passages. `quiet_hours` remains the selected valid answer, while its Choice probability changes 0.85 → 0.51 → 0.65 → 0.76 and confidence 0.71 → 0.26 → 0.57 → 0.72. Independent helpfulness changes 0.54 → 0.79 → 0.86 → 0.84. Outputs are not invariant to state changes, and semantic equivalence does not guarantee symmetric distribution shares. A low Choice confidence can describe competition among valid sources; independent relevance is a different proposition.

## Primary-source patterns read

The live [semantic-find cookbook](https://docs.typesafe.ai/cookbooks/semantic_find.md) pairs source-ID Choice with an answer-exists Noul. The [reranking cookbook](https://docs.typesafe.ai/cookbooks/rerank_typesafe.md) explicitly limits its improvement to a shortlist that already contains the relevant passage. [Composite scoring](https://docs.typesafe.ai/patterns/composite-scoring.md) supplies the reusable-axis pattern; [speculative fan-out](https://docs.typesafe.ai/patterns/fan-out.md) supports independent questions in one request while code consumes the applicable branch. The [skill-suggestion cookbook](https://docs.typesafe.ai/cookbooks/skill_suggestion.md) is a primary example of broad first-pass selection followed by narrow evidence inspection. Their published benchmarks and thresholds are not measurements of this corpus.

Three implementations were read as public source data, with fetched snapshots retained locally. [Hippo's Jev reranker](https://github.com/kitfunso/hippo-memory/blob/master/src/rerankers/jev.ts) asks independent candidate Nouls, rejects incomplete/out-of-range output and falls back to a local reranker. Its numeric candidate references differ from this experiment's named dictionaries. [Cheshi's recall rules](https://github.com/CheshiAI/Cheshi/blob/main/desktop/lib/chat-history-recall-rules.mts) separate direct answering evidence, related decision history and original direct record; neighbors resolve references rather than silently supply an absent answer. [Neo4jev's navigator](https://github.com/jexp/neo4jev/blob/main/src/neo4jev/navigator.py) combines observed-edge Choice and goal Noul with beam/depth/call budgets. This experiment transfers those patterns without running foreign code, installing the projects or requiring Neo4j.

The [Jev 1.13 limitations](https://docs.typesafe.ai/model-jaggedness/jev-1.13.md) describe indirection, irrelevant state, adversarial content, numeric/date handling and non-guaranteed relationships between separate judgments. Those documented cautions motivated named state, code chronology and retained per-question probabilities. The present data demonstrate specific failures; they do not prove every documented failure mode occurred.

## Limits and next falsifiable questions

This work shows feasible bounded compositions beyond a reranker. It does not choose a production retrieval architecture, write policy, graph database, embedding system or monthly cost. Before choosing one, evaluate an untouched real-source set with licensed/authorized source boundaries, paraphrases, project homonyms, incomplete histories, stale accepted decisions, missing answers and more distractors. Measure shortlist coverage, answering-source selection conditional on coverage, false answer-presence rate, required-facet coverage and end-to-end task usefulness separately.

A useful next experiment would compare lexical/hybrid/all-note candidates under an equal token budget; freeze goal facets before running graph variants; vary breadth while holding wording and thresholds fixed; and compare source-ID bundles with human judgments of useful context. Threshold calibration and ambiguity definitions need actual consequences and user labels. Generated prose and open-ended question generation would require a generative model and their own source-support checks; this study makes no generative claims.
