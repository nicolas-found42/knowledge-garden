# Repository deep dive: forming trustworthy knowledge from agent conversations

Date: 2026-09-29. This pass inspects implementation, questions, schemas, mutation policy and selected fixtures in **11 public repositories**, then evaluates four original, repository-inspired live experiment families. It extends the baseline research; it does not establish product decisions or production accuracy.

The strongest new direction is a wiki that can explain **why a note is eligible, what evidence is missing, and which derived assertions a source edit invalidates**. Jev supplies bounded semantic judgments. Source ownership, versions, counts, source copying and writes remain explicit code operations.

## Formation mechanisms and practical limits

### 1. Memsearch: distinguish journals, durable notes and procedural drafts

Memsearch’s [plugins/codex/scripts/parse-rollout.sh](https://github.com/zilliztech/memsearch/blob/2a4652fa086fbd45e92bfd8da7781ebe1642baa7/plugins/codex/scripts/parse-rollout.sh) normalizes actual Codex response/event messages, finds turn boundaries, distinguishes authored user/assistant text from host envelopes, and handles dual-written message duplicates. This is a useful reminder that source adapters still need exact event-schema knowledge. Semantic judgment can decide which authored content matters; it cannot reliably replace the transport parser.

Its [src/memsearch/maintenance.py](https://github.com/zilliztech/memsearch/blob/2a4652fa086fbd45e92bfd8da7781ebe1642baa7/src/memsearch/maintenance.py) fingerprints Markdown input paths and bytes, skips unchanged inputs, enforces a minimum interval and takes a task lock. The generation model returns `none` or `replace`; replacement writes the returned content directly to the configured output and updates maintenance state. The inspected `run_due_tasks` does not compare a fresh input digest immediately before that write. For a Knowledge Garden adaptation, source-version revalidation would therefore be a separate invariant rather than something to infer from “digest” or “lock.”

The [src/memsearch/prompts/memory_to_skill.txt](https://github.com/zilliztech/memsearch/blob/2a4652fa086fbd45e92bfd8da7781ebe1642baa7/src/memsearch/prompts/memory_to_skill.txt) distinguishes procedural memory from facts, decisions and preferences, requires recurrence across distinct sessions/days, retains corrected successful workflows despite intermediate failures, and makes candidates review drafts. It explicitly treats journals as lossy and asks for original transcript confirmation before emitting exact commands. This motivates Experiment D: decide whether the evidence warrants a scoped draft, then retrieve exact commands as a separate step. The [tests/test_maintenance.py](https://github.com/zilliztech/memsearch/blob/2a4652fa086fbd45e92bfd8da7781ebe1642baa7/tests/test_maintenance.py) covers response parsing, direct replacement, failure state and bounded transcript reading.

The [src/memsearch/jev_reranker.py](https://github.com/zilliztech/memsearch/blob/2a4652fa086fbd45e92bfd8da7781ebe1642baa7/src/memsearch/jev_reranker.py) asks independent source-for-answer Nouls, sends full candidate text in each question, checks exact answer coverage and finite probabilities, and raises rather than silently returning unjudged results. The candidate text is concatenated into instructions, which is a different trust boundary from putting it into state; an adaptation should state that candidate content is data and test embedded commands. This research did not demonstrate an exploit.

### 2. Total Agent Memory: keep temporal validity separate from semantic confidence

TAM’s [src/temporal_kg.py](https://github.com/vbcherepanov/total-agent-memory/blob/de53c19b6ae650459c96f0d297c5d33fd77e77b4/src/temporal_kg.py) records assertions with project, source, validity interval and recorded time. It deduplicates exact same assertions and, when `invalidate_previous=True`, closes assertions for the same subject/predicate/project according to effective time. It also handles a newly inserted older assertion by finding its later successor. These are deterministic operations once identities and a single-valued predicate are known. A model should not be asked to count timestamps or substitute for project partitioning.

The [src/contradiction_detector.py](https://github.com/vbcherepanov/total-agent-memory/blob/de53c19b6ae650459c96f0d297c5d33fd77e77b4/src/contradiction_detector.py) retrieves a bounded similarity shortlist of same-project decisions/solutions, asks a generation model whether a new record supersedes an old one, and uses confidence bands for superseded versus flagged records. Errors leave saving available and log an error. The source documents defaults including top-five candidates, similarity 0.55 and LLM confidence 0.8, but these are product defaults rather than evidence for our thresholds. A focused Jev replacement could select “global replacement / scoped exception / duplication / unresolved conflict,” while code preserves history and scope. A candidate missed by similarity cannot be judged at all.

### 3. Byeori: a missing retrieval result is not a missing piece of knowledge

The [src/byeori/jev_client.py](https://github.com/joonan-lab/byeori/blob/30a3045bea2ad2546fc7e3da1f8ac81b0cbd5b83/src/byeori/jev_client.py) builds a three-way `answer_only / needs_lookup / review_candidate` judgment from question, context, answer, cited excerpts, existing wiki passages, limitations and maintenance hints. Review requires all four conditions: a concrete discrepancy, reviewable evidence, likely reuse beyond one question, and a gap not already explained by recorded limitations or truncation. It explicitly distinguishes a missing retrieved passage from evidence that the wiki lacks knowledge.

Payload shrinking records every dropped passage/excerpt in state; if the core question/answer cannot fit, it returns no payload rather than trimming decisive text. [tests/test_jev_client.py](https://github.com/joonan-lab/byeori/blob/30a3045bea2ad2546fc7e3da1f8ac81b0cbd5b83/tests/test_jev_client.py) checks allowlisted fields, dropping order, exact response validation and preservation of below-cutoff probabilities. [src/byeori/lab_policy.py](https://github.com/joonan-lab/byeori/blob/30a3045bea2ad2546fc7e3da1f8ac81b0cbd5b83/src/byeori/lab_policy.py) gates offers using the raw `review_candidate` probability at 0.99 rather than generic confidence. This is an operational offer policy, not validated correctness or permission to publish.

[src/byeori/promote.py](https://github.com/joonan-lab/byeori/blob/30a3045bea2ad2546fc7e3da1f8ac81b0cbd5b83/src/byeori/promote.py) checks required frontmatter/provenance, source hashes, review state, required sections and placeholders, and records reviewer identity separately. A changed draft requires explicitly acknowledged review edits and conditional stored-hash checks. This supplies a strong local analogue: typed nomination → inspectable draft → content-version-checked acceptance. None of the AWS infrastructure is necessary to transfer that boundary.

### 4. Citation Verifier: deterministic existence and semantic support are different judgments

[src/lib/manuscriptCitations.js](https://github.com/MarissaFamularo/citation-verifier/blob/f9058642274033e62855d3066988418fefa2e272/src/lib/manuscriptCitations.js) accepts a proposed supporting quote only when it is found in source text or tables and checks stated numeric values. [src/lib/paperVerify.js](https://github.com/MarissaFamularo/citation-verifier/blob/f9058642274033e62855d3066988418fefa2e272/src/lib/paperVerify.js) handles numeric token boundaries, representational equality, statistical warnings and normalization. A numeric warning does not silently alter an existence-verification tier. These distinctions are useful for chat evidence: “the log printed exit 0,” “the agent claims success,” and “the feature meets its requirement” are different assertions.

[src/lib/typesafe.js](https://github.com/MarissaFamularo/citation-verifier/blob/f9058642274033e62855d3066988418fefa2e272/src/lib/typesafe.js) gives Jev a support/contradiction/silence Choice over a quote window, with full population/comparison/direction criteria. But `selectPassage` has an important caller precondition: when a supplied quote cannot be found in `source.text`, it returns that quote itself as an anchored passage. [src/lib/typesafe.test.js](https://github.com/MarissaFamularo/citation-verifier/blob/f9058642274033e62855d3066988418fefa2e272/src/lib/typesafe.test.js) explicitly tests this for a table-only quote. The surrounding [src/lib/pipeline.js](https://github.com/MarissaFamularo/citation-verifier/blob/f9058642274033e62855d3066988418fefa2e272/src/lib/pipeline.js) normally passes a quote that its upstream check proved against text/tables. Extracting the small Jev module without that upstream proof would lose the invariant. In our wiki, exact source identity/offset proof must accompany an “anchored” status; the judgment function alone cannot establish it.

### 5. Jev-Mem: multi-dimensional admission and non-destructive representations

The newly surfaced [memory/jev_questions.py](https://github.com/libingzheren/Jev-Mem/blob/7ab0c73c6d8f4f611ad252c1e6ba8083f8df0e44/memory/jev_questions.py) batches admission with independent episodic/semantic/procedural/preference judgments. Novelty is explicitly relative to the supplied recent memories, not a claim about the entire store. Relation questions separate association, causal direction and identity. Consolidation asks independent redundancy/contradiction/obsolescence/link questions alongside a representation Choice: retain separate, merge, promote repeated episodes, or uncertainty. This is richer than a one-label classifier.

[memory/memory_builder.py](https://github.com/libingzheren/Jev-Mem/blob/7ab0c73c6d8f4f611ad252c1e6ba8083f8df0e44/memory/memory_builder.py) keeps one canonical observation node with raw content, original text, temporal references and judgment metadata. It checks candidate existence before graph insertion and removes partial graph/vector insertion on failure. Consolidation retains original nodes, records relation votes, blocks summarization when contradiction crosses the threshold, and attaches source-memory IDs to generated representations. [tests/test_jev_mem.py](https://github.com/libingzheren/Jev-Mem/blob/7ab0c73c6d8f4f611ad252c1e6ba8083f8df0e44/tests/test_jev_mem.py) contains mocked-answer checks for contradiction blocking, preserved source nodes, idempotent links and no recursive summary cascade. They test composition rather than proving live model accuracy.

[memory/jev_mem_policies.py](https://github.com/libingzheren/Jev-Mem/blob/7ab0c73c6d8f4f611ad252c1e6ba8083f8df0e44/memory/jev_mem_policies.py) combines future utility/importance/novelty with redundancy in a weighted admission calculation and constructs a candidate set using embeddings, exact entity strings, keywords and time. Two adaptation cautions follow from the code: (a) admission can return `None`, so the memory graph is not an archival record of every imported turn; (b) shared entity strings create an exact-identifier link without another identity judgment, but the fallback entity extractor can produce those strings from capitalized names. Identical “Atlas” strings need not be globally unique entities. Preserve source scope and distinguish established entity IDs from extracted names.

### 6. ReallyArtificial: close the gap between a typed answer and a host operation

The [examples/02-memory-reconciliation/example.mjs](https://github.com/ReallyArtificial/jev-by-example/blob/088ae72890be5855a054b1d367589b3977c16c24/examples/02-memory-reconciliation/example.mjs) proposes replacement, scoped retention, duplication skip or review, with original evidence retained; its naive comparison is last-write-wins. The [examples/03-evidence-gaps/example.mjs](https://github.com/ReallyArtificial/jev-by-example/blob/088ae72890be5855a054b1d367589b3977c16c24/examples/03-evidence-gaps/example.mjs) checks claim IDs individually rather than asking for generated critique. [examples/04-semantic-cache-boundary/example.mjs](https://github.com/ReallyArtificial/jev-by-example/blob/088ae72890be5855a054b1d367589b3977c16c24/examples/04-semantic-cache-boundary/example.mjs) partitions by tenant, policy version and expiry before semantic interchangeability. Those exact checks belong in the host.

[examples/07-context-budget/example.mjs](https://github.com/ReallyArtificial/jev-by-example/blob/088ae72890be5855a054b1d367589b3977c16c24/examples/07-context-budget/example.mjs) pins mandatory snippets, asks separate relevance and novelty Scores and packs a character budget deterministically. It acknowledges greedy packing and novelty against already-known material rather than pairwise redundancy. [test/examples.test.mjs](https://github.com/ReallyArtificial/jev-by-example/blob/088ae72890be5855a054b1d367589b3977c16c24/test/examples.test.mjs) identifies authored-fixture replies as `authored-fixture-not-jev`, checks mandatory-budget behavior and ensures hard preflights prevent live requests. These are honest teaching contracts; fixture passes are not live Jev evaluation.

### 7. Extractive context and answering relevance need separate contracts

Shinpr’s [src/http.rs](https://github.com/shinpr/jev-reranker/blob/7bc72a1632a2c4048b2cf3ed47bb7e4701b82b27/src/http.rs) asks whether each source unit is needed for the answer, retaining conditions, exceptions, definitions and antecedents. [src/compression.rs](https://github.com/shinpr/jev-reranker/blob/7bc72a1632a2c4048b2cf3ed47bb7e4701b82b27/src/compression.rs) preserves source text across Unicode sentence boundaries; [src/ranking.rs](https://github.com/shinpr/jev-reranker/blob/7bc72a1632a2c4048b2cf3ed47bb7e4701b82b27/src/ranking.rs) preserves metadata/source order and assembles retained fragments. This suggests compact evidence bundles that copy exact source text instead of regenerating it, provided omitted qualifiers are independently checked. Selected text is not automatically a complete argument.

Hotchpotch’s [src/jev_reranker/instructions.py](https://github.com/hotchpotch/jev-reranker/blob/d58594b393b29b7ee6398cc9337dc5e9d6c6691e/src/jev_reranker/instructions.py) separates pairwise ordering from independent evidence retention and explicitly preserves partial/connecting facts. Its numeric anchors are instructions rather than calibration guarantees. Jev Recall’s [src/jev_recall/core.py](https://github.com/samdotmak/jev-recall/blob/d3e4acfb45c7cf6231f1621b7dafb09d21e95862/src/jev_recall/core.py) asks whether each memory would change what an assistant does, checks or mentions, including indirectly relevant constraints. It offers inline, pointer and shortlist modes with bounded request sizes. Together they support a broader input to knowledge formation: a short constraint can matter even when it resembles neither the user’s question nor the proposed note.

### 8. Two cautionary implementation details from context/search tools

Picaye’s [hermes-compact.mjs](https://github.com/picaye/jev-compaction/blob/ef5372d343eff22c1d5816d17d2742b16278dda3/hermes-compact.mjs) maps original Hermes messages to another compaction library, retains a reverse mapping and pins state-changing tools such as file writes and patches. Its comments describe a failure where windowed judgment dropped changes without the original goal/outcome context. It supplies the session goal to each window and keeps protected calls even if the model would drop them. The actual Jev questions live in a separate `src-repo/dist` dependency; this pass inspected the adapter boundary, not that dependency. For ingestion, preserved write/decision provenance should likewise bypass a relevance ranking when required by the archive contract.

Jevsearch’s [src/lib/jev-search-server.ts](https://github.com/kylemclaren/jevsearch/blob/1df37decb960b3c4826c71b41d3393c15a8f28d3/src/lib/jev-search-server.ts) combines per-candidate Nouls, one best-page Choice and answerability. An important difference from evidence filtering appears in implementation: if no hit clears the relevance threshold, it keeps the top three anyway. That is a reasonable browse-suggestion policy, but copying it into a grounded-answer pipeline would mean “no qualifying evidence” still yields context. Keep suggestions distinct from eligible evidence and expose answerability.

## Live experiments: four falsifiable capabilities

Exact inputs and labels were serialized in `experiments/formation-repos/cases.json` before calls. Each of 40 synthetic cases was run with a plain question and an evidence-aware variant, twice: **160 successful live SDK requests**, **240 labeled output fields**. Some evidence-aware requests also record diagnostic Nouls, which are not included in the accuracy totals. Calls used explicit `OPENROUTER_API_KEY`, SDK base URL `https://openrouter.ai/api`, requested model `typesafe/jev-1.13` and resolved model **`typesafe/jev-1.13-20260917`**.

The current TypeSafe [Python SDK guidance](https://docs.typesafe.ai/sdk/python.md), [Choice](https://docs.typesafe.ai/primitives/choice.md), [Noul](https://docs.typesafe.ai/primitives/noul.md), [citation cookbook](https://docs.typesafe.ai/cookbooks/citation_check.md) and [fan-out pattern](https://docs.typesafe.ai/patterns/fan-out.md) informed the contract. The [OpenRouter compatibility page](https://openrouter.ai/docs/guides/community/typesafe-sdk) had been read successfully in the parent session; fresh fetches in this branch returned 403/inaccessible. The same-session verified configuration was reused and all live SDK calls validated the route. SDK version: **0.7.2**. An HTTP response hook stores the successful raw provider JSON, since SDK serialization had discarded provider cost extras in the baseline work.

Total reported cost was **$0.004321968**, with **102,904 input tokens**, **10,548 output tokens**, **0.353s median request duration** and **15.10s total elapsed time** at five workers. This measures the experiment endpoint and synthetic payloads; it is not end-to-end ingestion performance. A JSONL journal flushes each completed response, and the final JSON contains exact prompts/questions, labels, full responses, model, usage, timings and checks. No private chat logs or synthetic credentials were sent.

### Baselines, interventions and failures

The registered simple baselines were intentionally weak: keyword-triggered wiki review scored 6/10; invalidating every note linked to an edited source scored 7/30; nominating every three-entry journal scored 4/10. The context baseline always chose the constructed topical distractor and scored 0/10. That last comparison is an adversarial negative control, **not a measured lexical-search implementation**. Reported improvements should therefore be read as rejection of those fragile rules, not victory over a strong ingestion/search system.

Evidence-aware variants made the source versus missing-context distinction explicit; impact judgments respected history and scope; context fetch questions stated what missing evidence a read must close. For procedural induction the host added exact distinct-session/completed-session counts and a recorded-abandonment flag. The model still judged recurrence meaning and whether failed attempts were later corrected. Exact counting is code's job.

Two genuine context-selection disagreements remained worth following up. For isolated “Yes, do that,” the evidence-aware selector chose no lookup twice, at confidence **0.41 and 0.33**, despite a predecessor fetch being available. The plain selector chose no lookup for “Actually, revert that choice” at **0.45 and 0.42**. Context-acquisition is therefore not ready as an ungated controller. A source window marked as containing an unresolved reference should force a read or review regardless of the winning option. An additional cause may be that fetch descriptions themselves contain answer evidence; a cleaner next experiment would supply source metadata alone and reveal actual source text only after selection.

Procedural induction incorrectly rejected one corrected workflow trial at confidence **0.10**. The “unsafe generalization” case had four further disagreements, but the label audit found a competing valid interpretation: only two sessions completed, below the policy's three-session minimum, so `none` is defensible. Similarly, the correction query asks only whether the first choice was abandoned, which may be answerable without identifying the named architecture. These ambiguities are recorded in `label-audit.json`. **The original labels/results remain unchanged**; post-hoc relabeling is not counted as an accuracy gain.

An exploratory confidence gate of 0.8 selected 74/120 plain labeled judgments and 102/120 evidence-aware judgments, with no original-label errors among the selected outputs. This threshold was analyzed after observing responses; it is not pre-registered calibration. It suggests a follow-up evaluation of confidence/coverage, with fresh labels and missing-context adversaries. The important operational distinction is that a correct classification can still lack enough provenance for a write.

## Concrete opportunities beyond semantic filing

1. **Source-dependent refresh planner.** Compute candidate dependents from exact source IDs in code; Jev judges whether an edited source invalidates each current assertion. Preserve historical records. Produce an evidence-linked refresh proposal rather than rewriting the whole topic page. Experiment B supports testing this next, with longer mixed-scope notes and source deletion cases.
2. **Maintenance nomination from failed answers.** Use question, attempted answer, cited evidence, prior wiki passages and explicit dropped/truncated markers. Jev distinguishes a useful new discrepancy from already-known limitations or missing retrieval. Code routes lookup and records a draft nomination. Experiment A is promising but should include genuine partial retrieval and adversarial quoted instructions.
3. **Evidence acquisition before claim promotion.** Select among observed read-only source locations—neighboring turns, current policy, test artifact, original quote—and then rejudge only with the actual fetched material. Reject the no-lookup branch when source metadata already establishes truncation or an unresolved reference. Experiment C exposed why this needs a staged, bounded host controller.
4. **Procedural candidate with an evidence ledger.** Exact session identities and outcomes constrain recurrence; semantic judgment distinguishes a workflow from a fact or temporary exception. A generation model can draft instructions only after original command evidence is retrieved. The result retains scope, sources and verification gaps. Experiment D supports a review-draft capability, not automatic installation.
5. **Representation selection with intact originals.** Novelty, contradiction, explicit replacement and representation choice can be recorded once and reused under different local thresholds. Generated summaries need source IDs and a separate support check; explicit contradiction blocks an automatic merge. Jev-Mem provides a source implementation for this composition, but it was not directly evaluated by our four live families.
6. **Extractive evidence bundle completeness.** Code proposes exact source units; Jev asks both whether each matters and whether every qualifier/antecedent is preserved. Budget packing pins mandatory provenance before ranking. This pattern combines Shinpr and ReallyArtificial, but our pass did not run a sentence-selection completeness experiment, so it remains an untested next capability.

The immediate prototype should preserve raw imported sources, record semantic votes as derived data, and make review proposals inspectable. It should use source fingerprints and content-version checks before accepting any note update. The evidence supports researching those capabilities; it does not yet choose a graph database, ingestion host or automatic knowledge-promotion policy.

```sh
/tmp/knowledge-garden-jev-venv/bin/python docs/research/initial-brainstorm/02-knowledge-maintenance/experiments/formation-repos/build_cases.py

```

`run.py` refuses to overwrite result/journal files. Reruns incur new paid calls; raw probabilities may vary. The dependency declaration is `typesafe-sdk==0.7.2`; the existing virtual environment supplies the SDK's `httpx2` transport. `cases.json` and both request variants should be reviewed before rerunning. Inspect `source-snapshots.json` for pinned source/license metadata; `results-initial.json` and `.jsonl` for exact requests/responses; `summary.json` for compact totals, `analysis.json` for deterministic summaries; and `label-audit.json` for ambiguities. Static source reading did not require executing any downloaded repository.
