# Precedents and local Mac stacks

Research date: 2026-09-29 (America/New_York); source capture timestamps are UTC and can fall on 2026-09-30. [Concern index](README.md). This report uses the [confirmed working specification](../../../../.scratch/ideas/current-specification.md) as authority and carries forward the [expanded synthesis](../../expanded-exploration/2026-09-29-synthesis.md). It proposes comparisons for the next specification interview; it selects no architecture or default home.

## Evidence and boundary

This is primary documentation and source-document inspection, not a hands-on usability study. Thirteen independently chosen app precedents were selected for specific behavior, spanning ordinary media, document research, visual knowledge, reading and answers. No user apps were opened or altered, no private assets copied, and no URLs recovered from conversations fetched. The [source manifest](experiments/source-manifest.json) records public URLs, acquisition status, timestamp, content hash and limitations. A successful HTTP response can be an empty JavaScript shell; those cases are explicitly identified below. Manufacturer speed, scale and simplicity claims are not measurements.

Version context: Tauri documentation is explicitly version 2; Electron documents use the mutable `latest` track; React Flow has a v12 migration entry; the inspected TheBrain page identifies version 15.0 and Curio identifies release 34. Other product pages did not establish an immutable application build. Tinderbox's attribute article carries a 2002 copyright and is a historical mechanism source, not evidence of its latest interface. Zotero's related-items documentation says last updated 2020-03-11. Captured hashes pin what was acquired, rather than pinning an installed release.

## Behaviors worth comparing on the same varied corpus

The strongest combination is an inference: keep a stable selection, scope and history while changing presentation. A clean page can open a temporary evidence panel; the panel can show that same material in a spatial arrangement; the canvas can return to the exact page. This should be compared with genuinely different concepts, not assumed to be the default. A global graph and a hand-arranged canvas answer different questions and need different rendering/state policies.

A compact disclosure system can cover all eight visualizer purposes without eight permanent panels:

| Required purpose | Candidate behavior to test | Evidence the task must expose |
| --- | --- | --- |
| Exploration | Related-item inspector, one-hop expansion, relationship filter | Why an item is suggested; recorded versus tentative/speculative edges |
| Explanation | Select an edge to open a source-linked comparison tray | Typed direction, supporting source revision, precise span and qualification |
| Orientation | Whole collection overview, explicit scope count, expandable groups, local depth | Full population remains reachable; aggregation does not hide source availability |
| Partial-memory finding | Preview grid plus person/place/time/format clues and semantic candidates | Active constraints, match explanation, missing extraction coverage |
| Comparison | Pin two sources/claims, aligned excerpts, version selection | Agreement/disagreement, exact qualifications, source versions |
| Change over time | Separate time-axis selector and sortable event list | Activity time versus reasoning event versus described event; uncertainty and unknown dates |
| Gaps | Filter unanswered questions, unsupported edges and inaccessible originals | Acquisition state distinct from epistemic status; absence is not evidence of falsehood |
| Trails | Ordered stops referencing existing items/spans, next/previous and overview return | Rationale and context for each stop; route persists as Markdown if saved |

Proposed concrete tasks: find a blue homework diagram from last spring with an uncertain date; identify the person shared by a photo and a PDF; compare a lecture slide's claim with a saved video's exception; explain a changed project decision using its earlier source; traverse a study trail mixing article, source photo and question. These are authored evaluation tasks. Neither manufacturer descriptions nor the previous 24-card laboratory establish human success, preferred clutter level or discoverability.

## Three viable Mac stack families, without selecting one

The documented primitives below support plausible implementations. “Possible” in the comparison means a reasoned integration path, **not** a completed prototype. No stack was installed, packaged or timed in this study.

**SwiftUI/AppKit with WKWebView** can combine native windows/menus/file access and web rendering. Apple's [WKWebView documentation](https://developer.apple.com/documentation/webkit/wkwebview) explicitly presents HTML/CSS/JavaScript alongside native views and exposes loading local-file content. [NSWorkspace](https://developer.apple.com/documentation/appkit/nsworkspace) opens files in external apps and reveals them in Finder. Inference: native shell and a web visualization surface can preserve quiet Mac navigation while sharing graph libraries with web prototypes. Costs to test include the bridge, focus/selection across native and web surfaces, WebKit compatibility, text accessibility and custom preview integration. SwiftUI alone does not provide a finished typed whole-collection graph.

**Tauri 2** uses a Rust host and the OS webview, with message passing and optional APIs rather than shipping a browser runtime. The [architecture docs](https://v2.tauri.app/concept/architecture/) support native extensions. The [file-system plugin](https://v2.tauri.app/plugin/file-system/) documents scoped file access and debounced `watch`/immediate `watchImmediate`; the [opener](https://v2.tauri.app/plugin/opener/) opens paths and URLs and reveals items. Inference: a web UI plus Rust ingestion/indexing is feasible, with native preview work crossing a bridge. OS WebKit versions remain part of the test matrix. Smaller distribution is a documented design intent, not a measured memory or latency advantage here. [Mac signing guidance](https://v2.tauri.app/distribute/sign/macos/) describes the distribution route.

**Electron** combines a main process, Chromium renderers and Node integrations according to its [process model](https://www.electronjs.org/docs/latest/tutorial/process-model). Its [shell API](https://www.electronjs.org/docs/latest/api/shell) opens files and reveals them. Inference: existing JavaScript conversion and visualization tools can fit naturally, and bundling Chromium reduces browser-engine variation. The extra runtime/process footprint must be measured on the same corpus. The [security checklist](https://www.electronjs.org/docs/latest/tutorial/security) requires careful renderer isolation and constrained privileges; imported HTML/Markdown must not become authority to operate files. [Signing](https://www.electronjs.org/docs/latest/tutorial/code-signing) still applies to distribution.

| Firm requirement | SwiftUI/WKWebView integration path | Tauri 2 integration path | Electron integration path | Shared unresolved proof |
| --- | --- | --- | --- | --- |
| Local first on Mac | Native file access and embedded WebKit | Rust file access and embedded OS webview | Main/Node file access and bundled Chromium | Offline inference policy, asset extraction and latency are not selected |

## Watchers, safe writes and rebuilds are cross-stack design work

Apple's archived [FSEvents introduction](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/Introduction/Introduction.html) documents directory-hierarchy change notifications; its [using-the-API guide](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html) requires recursive rescans for coalesced changes and full scans after dropped events. The guide is dated 2012, so it is a precise historical contract rather than an endorsement of every old sample API. Current [Node fs docs](https://nodejs.org/api/fs.html#fswatchfilename-options-listener) warn that replacing a watched file can leave the watcher on the old inode; filenames may be absent. Tauri exposes watcher modes but does not remove the need to reconcile file state.

Consequent research proposal, not selected architecture:

1. Watch a collection tree for invalidation; reconcile paths/content/IDs, rather than treating every notification as an authoritative complete operation log.
2. Reconcile on startup, resume, watcher error and explicit rebuild. Include atomic editor saves, directory rename, moving out and back, duplicate IDs, unknown files and mixed app/editor writes.
3. Parse complete stable file bytes; keep malformed external edits inspectable while exposing index error/staleness. Do not silently regenerate them.
4. A proposed app write records its base content hash and displays the Markdown diff. If external bytes changed, stop replacement and present a new proposal or merge comparison. No watcher alone establishes safe conflict handling.
5. Delete derived text/graph/embedding/thumbnail databases and rebuild from Markdown plus originals; compare durable IDs/relations/views/provenance and render/search outputs. Embedding model/version changes can change semantic ranking even after a correct rebuild, so record derivation versions.

These controls must preserve annotations, labels, saved queries, accepted/rejected/corrected relationships and view/trail arrangements in Markdown. Private database fields may accelerate them but cannot be their only record. Whether rejection decisions and historical revisions need separate records is still a specification question.

| [Sigma.js + Graphology](https://www.sigmajs.org/docs/) | WebGL graph rendering intended for thousands of nodes/edges | Whole-collection overview candidate. “Thousands” is library intent; measure labels, picking, typed parallel edges, grouping, workers and accessibility. Content cards/semantic grouping require extra UI. |
| [Cytoscape.js](https://js.cytoscape.org/) | Graph styling, selectors, events, algorithms, compound nodes and numerous layout extensions | Typed neighborhoods and expandable groups; performance depends on edges, styling and layout. Compound nodes are not automatic evidence-aware clusters. Check actual renderer/version rather than assuming all Canvas/WebGL modes share results. |
| [React Flow](https://reactflow.dev/learn) | Custom nodes/edges, subflows, whiteboard patterns and accessibility/performance guidance | Rich excerpts/media on a focused canvas. A DOM-heavy card canvas is not demonstrated to replace a large global graph. Coordinate edits must persist in Markdown if saved. |
| [vis-timeline](https://visjs.github.io/vis-timeline/docs/timeline/) | Points, intervals, groups, zoom/pan and sorting controls; HTML-based rendering | Explicit activity/reasoning/described-event lanes with read-only editing. Unknown dates need a separate list or explicit bucket; a start/end interval must not turn uncertainty into asserted duration. |
| [SQLite FTS5](https://www.sqlite.org/fts5.html) | Tokenizers, MATCH queries, phrase/prefix searches, ranking, snippets and highlighting | Rebuildable lexical index with source-span mapping. It does not supply embeddings, OCR, graph traversal or grounded answers. Test extraction/index coverage separately from ranking. |
| [PDF.js](https://mozilla.github.io/pdf.js/) | Browser PDF rendering | Cross-stack PDF surface candidate. Rendering does not establish extraction/annotation fidelity for every PDF; page anchors need source identity/version. Other formats need adapters or native external-open fallback. |

Semantic/vector indexing is an additional derived layer, not a substitute for keyword/metadata search or relational traversal. An in-memory graph built from Markdown can evaluate visual queries independently of rendering. Storing graph layout snapshots or saved visual queries only in Graphology/React state would violate the durable-record contract. These are engineering inferences, not measurements.

## Source opening and packaging details that affect the comparison

A successful external-open API does not guarantee precise location navigation. Distinguish: open retained original; reveal it; open page/block/time/region; report that only the enclosing source could be opened. Heptabase's fallback behavior is a useful precedent for making that distinction. Original formats should remain available even if inline rendering or extraction is unsupported.

Apple's current [sandbox file-access documentation](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox) describes user-selected access and explicit security-scoped bookmarks for persistence across launches. This concerns **sandboxed** distribution; a direct-distribution app need not automatically inherit every App Store constraint. The [App Sandbox documentation](https://developer.apple.com/documentation/security/app-sandbox) states that Mac App Store distribution requires sandboxing. Test a selected collection, its copied originals, external-editor open and permission recovery under the intended packaging route.

Apple's [notarization guidance](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) separates notarization from App Review. All candidate families need a real signed/notarized artifact test if that distribution route is chosen, including bundled helpers, extractors and model binaries. Availability of a framework's bundler does not establish a working release with those components. Mac minimum version, Apple Silicon/Intel support and App Store versus direct distribution remain open; do not use speculative requirements to eliminate a viable stack.

## Access failures and what remains untested

The web extraction tool returned restricted-URL/internal errors for several Obsidian, Apple, DEVONthink and other pages. Direct public HTTP capture recovered most content. Obsidian Help yielded only application shells, so official repository Markdown was inspected. Apple WebKit/NSWorkspace JSON documentation and official Markdown endpoints recovered JS-only developer content. The obsolete Kagi `search/quick-answer` path returned 404 and `docs.kagi.com` failed DNS; the current official `help.kagi.com/kagi/ai/quick-answer.html` succeeded. Photos redirected to a guide overview; no specific search interaction was claimed. These are acquisition failures, not evidence of missing application features.

No installed precedent was tested for accessibility, keyboard ergonomics, external editing, scale or offline operation. No stack prototype or package was built. No full-collection graph performance number, timeline uncertainty usability result, general-file extraction support claim or automatic merge safety claim follows from this report. The neighboring experiment concerns must supply measured evidence and label their limits. This report supplies primary-source mechanisms, competing integration paths and concrete tests while preserving every firm requirement.
