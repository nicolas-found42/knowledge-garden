# Initial local media experiment

Status: NOT VERIFIED. This experiment is not an application acceptance test.

On the M5 Pro Mac with 48 GB unified memory, Ollama 0.40.13 installed `qwen2.5vl:7b`, model ID `5ced39dfa4ba`, Q4_K_M, reported as 8.3 billion parameters. The model blob is 5,969,233,408 bytes. Ollama's model store used 5.6 GiB after installation. The existing local Whisper large-v3-turbo asset is 1,624,555,275 bytes and its pinned revision is in `src-tauri/resources/audio/ASSET-MANIFEST.txt`. The model's supported inputs in this runtime are text and images, so audio requires a separate local component. See [Ollama's model page](https://ollama.com/library/qwen2.5vl) and [Qwen's Omni model card](https://huggingface.co/Qwen/Qwen2.5-Omni-7B) for the distinction between runtime and model capabilities.

An isolated video was built from the repository's `fruits.jpg` and `frozen-two-speaker-uncertain-correction.wav` using FFmpeg. The video has both streams. A frame at five seconds showed fruit. Whisper extracted speech from the video and returned intervals 0.00 to 4.30 seconds for the original report of 12 visits and 5.44 to 11.38 seconds for the uncertain correction that the count could be 15. These timestamps are estimates. Qwen correctly identified several visible fruits, but incorrectly described the kiwi's colors. A subsequent request supplied the frame and transcript together. It reported an orange and the count, but falsely connected the count to the orange and omitted requested timestamps. The combined semantic judgment failed the negative assertion against an invented relationship.

One standalone Whisper run took 8.38 seconds including a cold Metal compilation on a busy machine. Its process reported 2,030,422,368 bytes peak memory footprint. A single cold Qwen image request took 8.61 seconds; the loaded runner's later resident set was about 9.1 GiB. That is a snapshot, not a measured peak or a production benchmark. These measurements do not establish headroom under concurrent application workloads. The video, frame, transcript and model responses for this exploratory run are under `/tmp/knowledge-garden-pivot-experiment` and are not durable acceptance evidence.

`python3 scripts/probe-local-media.py` repeats the isolated fixture. A second run reproduced the same incorrect kiwi description and false orange-to-visits relationship. A separate yes/no question correctly rejected that relationship, but one correct answer does not establish a reliable guard. Use separate evidence records and validate relationships against their cited evidence.

Before selecting the final runtime, capture reliable process-level peak measurements and test under the application's actual workload. Verify non-speech audio coverage or disclose a precise limitation. Verify the complete app with source-linked frame and audio locations.

## Setup-check instrumentation

In a uniquely identified debug bundle with an empty isolated collection, the setup panel ran Qwen on a one-pixel synthetic image using its own Ollama service. `scripts/sample-process-tree.py` observed the app and its children for 16.8 seconds at a nominal 250 ms interval. The kernel-reported lifetime physical-footprint peak for the observed inference runner was 3,742,801,744 bytes; the largest sampled sum of physical footprints across observed descendants was 4,414,188,944 bytes. Search opened while the model check was running. This is an instrumentation check, not representative media processing or a responsiveness benchmark. Short-lived processes can be missed, summed process footprints can double-count shared memory, and process footprint does not establish the full unified-memory or GPU-driver cost. An unrelated Ollama runner was also already loaded. Measure the final application, audio/video workload, system pressure and practical headroom separately.
