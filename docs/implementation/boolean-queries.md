# Boolean relationship queries

Open any knowledge page and choose **Build Boolean query**. All controls are native labeled form controls and work with Tab, Shift-Tab, arrow keys and Enter. Add or remove path clauses, hops, page conditions and nested groups. Group operators combine page sets: AND intersects, OR unions, and NOT complements within the currently indexed collection. An empty AND selects the indexed set; an empty OR selects nothing. The visible expression shows every clause, arrow and scope; changing any field removes previously calculated results until **Run query** calculates the changed expression. **Clear query** clears all conditions and returns to an empty AND. Normal Sources, Search and page navigation remain available for excluded pages.

A path starts at a knowledge page ID and follows exactly the listed hops. A hop names a stored relationship type and selects **with_arrow** or **against_arrow**. Types are exact labels; a similarity relation remains similarity, and an uncertain relation retains its evidence and qualifier. Paths can return to their starting page through cycles. The executor tracks each `(clause, depth, page)` separately; one deterministic supported route per matching positive path clause explains each returned page. It does not imply that every possible route has been enumerated.

Date constraints compare the indexed event date inclusively, never the import date. Undated pages do not satisfy a date constraint. Format and processing status describe the source that supplies the indexed page. **Endpoint** constraints apply only to the final page of a path. **Intermediate** constraints apply to every page reached before the final hop, excluding the starting page. Returned-page conditions and **Constraints on returned page set** apply to returned pages, including source pages where applicable. Changing the scope selector edits the corresponding independent scope; both scopes remain visible in the expression. Blank values remove the condition.

NOT says a page is outside a specified indexed set. It never asserts that an unsupported real-world relationship is false. Missing endpoints or unavailable support are disclosed as diagnostics, and no positive route is fabricated. Pages selected solely by metadata or negation state that no positive connecting path is asserted.

The public `Application::query_pages` and desktop `query_pages` operations accept the typed Boolean expression, returned constraints, work budget, result page size and an opaque continuation. Local SQLite adjacency lookups and page metadata lookups advance a bounded amount per request. Path clauses finish before the returned-set scan begins, so negation never interprets incomplete traversal as a final answer. **Continue query** advances the next bounded batch. **Cancel query** marks the current session canceled and suppresses in-flight replies; edited clauses supersede earlier replies. Navigating to a result and using Back restores expression, selected result, counts and scroll. An index revision change invalidates current results and evidence tokens and asks for a fresh run.

The input contract limits a single query to 64 clauses, 16 levels of grouping and 32 typed hops per path, with explicit validation errors. The default reader batch budget is 50 work units; native callers can request 1–50 units and 1–50 returned pages. One frontier adjacency advancement or candidate-page evaluation consumes one unit; each candidate evaluates the bounded expression and retains only explanatory positive clauses. Disposable query state and tokens expire after the path-query idle timeout. The engine does not load the collection graph or generate an answer.
