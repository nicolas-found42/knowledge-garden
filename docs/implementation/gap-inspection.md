# On-demand knowledge gaps (#24)

Source and knowledge readers expose a collapsed **Inspect knowledge gaps** panel.
Opening or refreshing it inspects current persisted state; it creates no approval
queue or changes to semantic output. Explanations give category, affected scope,
what is known, recovery status, evidence when available, and a contained retained
original handoff. Relationship originals use their precise supported version.

Categories distinguish unavailable source material, incomplete extraction,
pending update, failed/uncertain update, ambiguous identity, and insufficient or
qualified relationship support. Ambiguity is reported from existing recovery
errors or duplicate page identities; labels alone never assert that same-name
entities are the same. Qualified relationships also carry a visible textual badge
and dashed boundary in path details, alongside their preserved qualifiers.

Search status facets include replacement and extraction states, and unavailable
originals no longer prevent index rebuild or readable-page access. Reinspection
replaces old explanations after recovery; an inspection failure is explicitly
unavailable, never an empty successful report. Explanations are bounded to 100.

Application fixtures exercise provider recovery, a still-unsupported source,
qualified and missing relationship support, duplicate preserved owner identities,
partial/failed/ambiguous persisted updates and status search. Component tests
exercise collapsed access, refresh narrowing, precise original handoff and late
response rejection. Native-driver browser inspection covers actual readable
sources and gap details. Broad accessibility qualification remains issue #32.

Extraction detail and coverage record their producing source version independently
of the pending update. Extraction and update explanations therefore bind different
originals when a new candidate fails before producing extraction. Legacy records
with unknown ownership disclose that limitation and do not choose an asset.
