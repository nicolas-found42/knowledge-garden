# Local meaning search

The reader's **Search mode** selector keeps ordinary title/keyword search and adds **Remembered meaning**. Meaning results are existing pages with their original title, excerpt, filters, and navigation behavior; the application does not generate a search answer.

The Rust search path uses BAAI's `bge-base-en-v1.5` English ONNX model, CLS pooling with L2 normalization, the publisher's short-query prefix, and a local USearch HNSW index. Current FTS page documents are split into bounded 510-token chunks. Each vector key is derived from the stable page ID and chunk number; a SQLite side table maps returned keys back to page IDs and source excerpts. Content hashes skip unchanged pages during synchronization. Removed page entries are removed from both stores. The meaning index is disposable and synchronized during Application open/rebuild.

Run `npm run package:app` to provision verified model/runtime resources and package them into the macOS app. Provisioning fetches only at build time when a valid local copy is unavailable, checks every model/tokenizer/runtime digest, checks the runtime architecture and dynamic-library dependencies, and includes upstream notices. Queries never download model files. `KNOWLEDGE_GARDEN_MEANING_ASSETS` can point a local Application test at an already provisioned resource directory; the desktop app resolves its bundle resource directory itself.

When assets are absent, damaged, or incompatible, the result payload reports `missing_assets:` or `incomplete_index:` and meaning mode returns no pages; keyword search remains available. Rebuilding from current page-search records preserves page IDs. The model is English-only. A three-query no-result calibration set selected an abstention cutoff of 0.45; the eight fixed relevant cases scored 0.544–0.848 and three calibration nonmatches scored 0.398–0.413. These small synthetic observations validate only this bounded path and do not establish general quality or 250,000-source performance.
