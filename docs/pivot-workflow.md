# Self-maintaining library pivot workflow

The goal is complete only when every required acceptance case in the supplied objective passes against the installed application, existing and new collections survive a verified migration, and the tested commit is on remote main. Any inconclusive gate remains open.

This is a high-rigor change. It crosses source acquisition, durable data, model execution, derived knowledge, and the application interface. The repository contains roughly 943 tracked files. The existing checkout has unrelated uncommitted files and a Jev identifier edit; preserve them until their purpose and ownership are clear. Existing ADRs 0001, 0002, and 0004 conflict with the requested authority and provider policy and must be superseded.

1. Capture baseline tests, existing code and data layout, machine capacity, and existing changes. Build the acceptance matrix and isolate test collections.
2. Research and run a local Qwen pipeline on photograph, audio, and video fixtures. Record model revision, sizes, peak memory, timings, and actual semantic evidence. Do not integrate a runtime until this gate passes.
3. Design source identity, processing states, durable jobs, evidence, removal, and recovery around actual data access and concurrent operations. Back up existing collections before migration.
4. Implement centrally enforced provider and derived-content authority, universal source intake, bounded extractors, and autonomous maintenance in independently verified units.
5. Implement recoverable removal, re-addition, migration, and refresh with regression checks for concurrency, restarts, and independent support.
6. Finish the library interface and operational health information. Exercise real fixtures in an isolated collection through the actual application.
7. Run the acceptance matrix, required repository checks, production build, and migration recovery. Review the diff and documentation, integrate current remote main, repeat affected checks, commit and push without force, and verify the remote SHA.

Each unit records a hypothesis, evidence, and VERIFIED, NOT VERIFIED, or INCONCLUSIVE outcome in the decision log. Unknown extraction formats must remain retained and honestly reported. A settled collection must become idle. No partial result satisfies the final gate.
